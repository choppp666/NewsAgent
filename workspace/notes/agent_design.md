# Agent 设计笔记

## 为什么优先手写 Function Calling 循环

框架会隐藏「谁决定下一步」这件事。手写一遍之后能看到三件关键事实：

1. **调用顺序是模型给的**，不是代码分支给的——去掉 `if tool == "x"` 之后，程序只剩一个循环；
2. **停止条件也是模型给的**：某一轮不再返回 `tool_calls`，循环自然结束；
3. 工具结果必须**原样回填**成 `role="tool"` 消息，模型才能基于新事实继续推理。

## 关键约束

- 最大轮数（防止无限调用）
- 单次工具超时（防止命令挂死）
- 结果截断（防止上下文爆炸）
- 工具名不存在时回传错误而不是抛异常（让模型自我纠正）

## 与 ReAct 的关系

ReAct = Reasoning + Acting，本质是把「思考」与「行动」交替写进同一个上下文。
原生 Function Calling 相当于 ReAct 的结构化版本：`tool_calls` 就是 Acting，
`content` 就是 Reasoning，但不需要模型输出特定格式的文本让人去解析。
